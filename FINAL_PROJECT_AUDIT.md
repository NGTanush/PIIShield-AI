## 2. Detailed Audit by Project Module

### 2.1 Core Detection (`detection/pii_detector.py`)
- **Status:** Complete & Tested
- **Supported Entity Types:** `PERSON`, `EMAIL`, `PHONE`, `LOCATION`, `DATE`, `ADDRESS`, `IDENTIFICATION_NUMBER` (SSN, Aadhaar, PAN, Credit Card, IP).
- **Architecture:** Hybrid approach. Regex scans high-precision structured tokens; spaCy NER (`en_core_web_sm`) extracts unstructured names, locations, and organizations.
- **Overlap Resolution:** `merge_entities()` sorts by character start and resolves overlapping spans by score confidence and priority.

### 2.2 Masking Engine (`masking/pii_masker.py`)
- **Status:** Complete & Tested
- **Strategy A (Basic):** `[PERSON_1]`, `[EMAIL_1]` — sequential typed tokens.
- **Strategy B (Random Typed):** `[PERSON_X7K92]` — typed token salted with 5-character SHA-256 entropy.
- **Strategy C (Opaque):** `ZXQ7K92M` — 8-character token completely concealing entity semantic category.
- **Strategy D (Protected):** `[PROT:PERSON:P1:C4D9]` — embeds 4-character cryptographic CRC MD5 checksum for deterministic tamper verification.
- **Repeated Entities:** Reuses existing placeholder for identical string values within a prompt to preserve coreference.
- **Reverse Mapping Order:** Replacements performed in descending order of character start position to preserve offset boundaries.

### 2.3 LLM Integration Layer (`llm/llm_processor.py`)
- **Status:** Complete & Tested
- **Local LLM:** Ollama integration via `http://localhost:11434` with configurable timeout and error trapping.
- **External API:** OpenAI-compatible endpoint with bearer token authentication (`LLM_API_KEY`).
- **Demo / Mock Mode:** 8 distinct perturbation scenarios:
  1. *Normal* (Preservation)
  2. *Paraphrasing* (Contextual rephrasing)
  3. *Summarization* (Condensation)
  4. *Translation* (French translation with potential token corruption)
  5. *Grammar Correction* (Spelling/syntax normalization)
  6. *Placeholder Modification* (Brackets stripped / casing altered)
  7. *Placeholder Deletion* (Tokens dropped)
  8. *Placeholder Duplication* (Spurious duplicate tokens)
- **Provenance Tagging:** Every response explicitly tagged as `REAL_LLM`, `SIMULATED`, or `BENCHMARK`.

### 2.4 Placeholder Validation Engine (`validation/placeholder_validator.py`)
- **Status:** Complete & Tested
- **Seven Failure Categories Implemented:**
  1. `CORRECT`: Exact match passing format and checksum.
  2. `MISSED`: Replaced by a noun phrase or pronoun.
  3. `DROPPED`: Completely missing from response.
  4. `INFLECTED`: Brackets stripped, casing changed, or punctuation mutated.
  5. `MISTRANSLATED`: Identifier translated into another language.
  6. `HALLUCINATED`: Spurious placeholder generated by LLM.
  7. `CROSS_WIRED`: Multiple tokens swapped positions or binding.
- **Cryptographic Tamper Detection:** Strategy D checksums verified against `hashlib.md5(val)[:4].upper()`.

### 2.5 Safe Restoration Engine (`restoration/pii_restorer.py`)
- **Status:** Complete & Tested
- **Zero-Leakage Principle:** Only tokens classified as `FailureCategory.CORRECT` are permitted for downstream restoration.
- **Rejection Handling:** Dropped, inflected, mistranslated, and hallucinated tokens are left unrestored or replaced with explicit warning tags (`[UNKNOWN]`).
- **Audit Logging:** Every restoration action logged with status (`RESTORED`, `UNRESTORED`, `REJECTED`, `SKIPPED`).

### 2.6 ML Failure Prediction (`evaluation/failure_predictor.py`)
- **Status:** Complete & Tested
- **Feature Vector:** 27-dimensional encoding (9 entity categories, 4 masking strategies, 9 perturbation scenarios, prompt token count, entity density, language code, index).
- **Models Evaluated:**
  - *Baseline:* Logistic Regression (Accuracy: 81.8%, Precision: 72.3%, Recall: 53.1%, F1: 61.3%).
  - *Ensemble:* Random Forest (Accuracy: 78.4%, Precision: 63.8%, Recall: 46.9%, F1: 54.1%).
- **Leakage Prevention:** Group-aware splitting (`GroupShuffleSplit`) ensures all entities from the same base prompt reside strictly in train or test split.
- **Disclaimers:** Explicitly marked as experimental in UI and logs.

### 2.7 Dataset Infrastructure (`dataset/`)
- **Status:** Complete & Tested
- **Synthetic Benchmark:** 300 base prompts, 852 annotations across 7 PII categories.
- **Offset Verification:** 100% of annotations satisfy `assert original_text[start:end] == value`.
- **Public Kaggle Benchmark:** Integrated via `dataset/public_benchmark/` with 10-essay educational sample (53 entities) in full competition BIO format.
- **Separation Guarantee:** Public Kaggle dataset used strictly for detection benchmarking; synthetic dataset used for round-trip restoration evaluation.

### 2.8 Database & Provenance (`database/db_manager.py`)
- **Status:** Complete & Tested
- **Schema:** Tracks ID, name, masked text, raw LLM response, restored response, metrics, failure distributions, provenance, and timestamps.
- **Micro-Averaged Aggregation:** Computes true ratio-of-sums ($\frac{\sum C}{\sum A}$, $\frac{\sum C}{\sum E}$) preventing unweighted ratio distortions.
- **Zero PII Storage:** Raw plaintext values are explicitly omitted from table columns.
